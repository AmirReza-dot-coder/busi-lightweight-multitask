# راهنمای بررسی پروژه BUSI

این بسته برای بررسی کدها، نتایج و نمودارهای پایان‌نامه آماده شده است. منبع هر جدول در `docs/result_provenance.csv` مشخص است و بسته‌های خام نتایج بدون تغییر نگه‌داری شده‌اند.

## مسیر پیشنهادی برای استاد

۱. ابتدا `README.md` و `docs/CLAIMS_AND_LIMITATIONS.md` را بخوانید تا تفاوت مطالعهٔ حذف اجزا و مطالعهٔ کنترل‌شدهٔ تک‌وظیفه‌ای/چندوظیفه‌ای روشن باشد.

۲. کدهای اصلی در پوشه‌های `notebooks` و `src` هستند. نوت‌بوک‌های `exploratory` به آزمایش‌های تکمیلی تعلق دارند. نوت‌بوک قدیمی آماده‌سازی در `legacy` است.

۳. جدول‌های اصلی در `results/tables` و نمودارهای ساخته‌شده از همان اعداد در `results/generated/figures` قرار دارند. نتیجه‌های هر اجرا، پیش‌بینی هر تصویر، ماسک‌های سخت و سوابق آموزش در فایل‌های ZIP پوشهٔ `results/archives` قابل بررسی‌اند.

۴. برای کنترل عددی نتایج، در محیط Python این دستورها اجرا شوند:

```bash
python -m pip install -r requirements-review.txt
python tools/rebuild_review.py
```

این برنامه، بدون دیتاست خام و بدون وزن مدل، از روی پیش‌بینی‌ها و ماسک‌های ذخیره‌شده معیارها را دوباره محاسبه و نمودارها را تولید می‌کند. ۲۸۸ مقدار با جدول‌ها تطبیق داده شده‌اند. این کنترل، اجرای دوبارهٔ آموزش یا inference نیست.

## وضعیت فایل‌های لازم برای اجرای مدل

تقسیم ثابت `data/split_manifest.csv`، مشخصات معماری و تنظیمات اجراها داخل بسته هستند. تصاویر BUSI و وزن‌های `.keras` باید جداگانه در اختیار بررسی‌کننده قرار بگیرند.

فهرست ۲۸ رکورد وزن با ۲۷ SHA256 یکتا در `data/required_checkpoints.json` ثبت شده است. برای آماده‌کردن این فایل‌ها، نوت‌بوک `notebooks/Export_Advisor_Checkpoints.ipynb` را در Colab باز کن؛ فایل‌های `tools/export_checkpoints.py` و `data/required_checkpoints.json` را در سلول مربوط بارگذاری کن. خروجی در پوشهٔ `BUSI_ADVISOR_CHECKPOINTS` در Drive خودت ساخته می‌شود. این برنامه آموزش انجام نمی‌دهد و دسترسی پوشه را تغییر نمی‌دهد.

اجراهای تاریخی به ساختار پوشه‌ها و فایل‌های شروع ثبت‌شده در Drive وابسته‌اند. راهنمای دقیق در `docs/RUNNING.md` آمده است. برای بازتولید کامل، پوشهٔ اصلی آزمایش‌ها، به‌ویژه مدل‌های اولیه و فایل‌های تنظیمات کنار آن‌ها، باید نگه‌داری شوند.

## قرار دادن بسته در GitHub

- یک Repository با نام پیشنهادی `busi-lightweight-multitask` بساز. برای بررسی اولیهٔ استاد می‌توانی حالت Private را انتخاب کنی.
- فایل ZIP این بسته را روی کامپیوتر Extract کن. **محتویات داخل پوشهٔ پروژه** را در ریشهٔ مخزن بارگذاری کن تا `README.md` در صفحهٔ اول دیده شود.
- خود فایل ZIP بیرونی را به‌عنوان تنها فایل مخزن آپلود نکن؛ کدها، CSVها و PNGها باید قابل مشاهده باشند. ZIPهای داخل `results/archives` نسخه‌های خام نتایج‌اند و باید همراه ساختار بمانند.
- قبل از فرستادن لینک، یکی از نوت‌بوک‌ها، یک جدول و یک نمودار را در GitHub باز کن و نمایش آن‌ها را بررسی کن.
- اگر مخزن Private است، از بخش Settings → Collaborators → Add people، استاد را با حساب یا ایمیل درست خودش دعوت کن. لینک خصوصی به‌تنهایی دسترسی ایجاد نمی‌کند.
- لینک مخزن را پس از ساخت واقعی آن برای استاد بفرست. لینک وزن‌ها و دیتاستِ مرتب‌شده را در صورت نیاز جداگانه اضافه کن.

راهنمای رسمی GitHub: https://docs.github.com/en/repositories/creating-and-managing-repositories/creating-a-new-repository

## نکات علمی ضروری

اعداد مطالعهٔ تک‌وظیفه‌ای/چندوظیفه‌ای از validation و checkpointهای منتخب ویژهٔ هر وظیفه آمده‌اند. ترکیب بهترین عدد دو checkpoint به‌عنوان عملکرد هم‌زمان یک مدل صحیح نیست. گروه‌های شباهت BUSI نیز شناسهٔ تأییدشدهٔ بیمار نیستند.

وضعیت خام کنترل نهایی، یعنی `REVIEW_REQUIRED`، حفظ شده است. دو اختلاف ثبت‌شده دربارهٔ مساحت پیش‌زمینهٔ کاذب تصاویر نرمال در آزمون تاریخی به تغییر تک‌پیکسلی مربوط‌اند؛ گزارش خام از بسته حذف یا بی‌علامت نشده است.

ارزیابی خارجی BUS-UCLM هنوز انجام نشده و در این بسته نتیجه‌ای برای آن گزارش نمی‌شود.
